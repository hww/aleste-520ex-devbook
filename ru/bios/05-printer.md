# 05-printer.md — Драйвер принтера (BIOS.DRV)

## Назначение

Выводит символы на принтер через параллельный порт (Centronics) или последовательный (RS-232), в зависимости от настроек `SETUP`. Драйвер проверяет готовность принтера, обрабатывает `Ctrl+C` для прерывания длительной печати и издаёт короткий звуковой сигнал через AY8910 при отправке байта (для диагностики).

Это **не CPC-овский принтер** через PPI. Aleste использует отдельный порт управления, а выбор интерфейса (параллельный/последовательный) определяется битом в `SETUP+18H` (см. `ROM.MAC`). Драйвер принтера в `BIOS.DRV` работает **только с параллельным портом** — последовательный вывод, вероятно, выполнялся через `COM_OUT` (отсутствует).

**Исходник:** `BIOS.DRV` (подключается через `INCLUDE BIOS.DRV` в `BIOS.MAC`).

---

## Вывод

### `LPTOUT` (`L012F`)

Вывод одного символа на принтер. Ждёт готовности (`LPTSTT`), проверяет `Ctrl+C` (`BREAK`), отправляет байт и издаёт короткий писк через AY8910.

```
Вход:  A = код символа
Выход: CF=1 если нажат Ctrl+C (символ не отправлен, отправлен CR)
       CF=0 если отправлен
Изменяет: AF
```

**Логика:**
1. Вызывает хук `XFDDB` (LPTOUT hook).
2. В цикле: проверяет `BREAK` (если `Ctrl+C` — отправляет `CR` и выходит с `CF=1`), проверяет `LPTSTT` (если занят — повторяет).
3. Отправляет байт через `LPTOUT_3`: пишет `0FH` в AY8910 (регистр 0FH — громкость канала A?), затем манипулирует портом `0F6xxH` (строб `STB`).
4. Возвращает `CF=0`.

**Пример:**
```asm
    LD   A,'H'
    CALL L012F      ; LPTOUT
    JR   C,ABORTED  ; Ctrl+C
    LD   A,'i'
    CALL L012F
```

**Пример (печать строки):**
```asm
PRINT_STR:
    LD   A,(DE)
    AND  A
    RET  Z
    CALL L012F
    RET  C          ; Ctrl+C — прервать
    INC  DE
    JR   PRINT_STR
```

## Проверка готовности

### `LPTSTT` (`L0132`)

Проверка готовности принтера. Читает порт `0F5xxH` (статус) и проверяет бит `BUSY`.

```
Вход:  —
Выход: A = 00, ZF=0 если готов
       A = FF, ZF=1 если занят
Изменяет: AF
```

**Логика:** читает `0F5xxH`, дважды `RLCA` (сдвигает бит `BUSY` в бит 0), `CCF` (инвертирует), `SBC A,A` (превращает в `00` или `FF`). Если `BUSY=0` (готов) — `A=00, ZF=0`; если `BUSY=1` (занят) — `A=FF, ZF=1`.

**Пример:**
```asm
WAIT_READY:
    CALL L0132
    JR   Z,WAIT_READY   ; ZF=1 — занят, ждём
    ; принтер готов
```

## Внутреннее устройство

### `LPTOUT_3`

Низкоуровневая отправка байта. Пишет `0FH` в AY8910 (регистр 0FH), затем манипулирует портом `0F6xxH`:

```
    LD   D,0FH
    CALL WR_PSG      ; AY8910 reg 0Fh = 0Fh
    DI
    LD   E,B
    LD   B,0F6H
    IN   A,(C)       ; читаем текущее состояние порта
    AND  30H         ; сохраняем биты 4-5
    OR   10H         ; устанавливаем STB (бит 4)
    OUT  (C),A       ; STB = 1
    EX   (SP),HL     ; задержка
    EX   (SP),HL
    AND  20H         ; сбрасываем STB, оставляем бит 5
    OUT  (C),A       ; STB = 0 (строб)
    LD   B,E
    EI
    RET
```

**Что здесь происходит:** бит 4 порта `0F6xxH` — это `STB` (strobe) для Centronics. Бит 5 — вероятно, `AUTO LF` или `INIT`. Последовательность `STB=1 → задержка → STB=0` — стандартный стробирующий импульс.

**Зачем `WR_PSG`?** Вероятно, для диагностики: если принтер не отвечает, звук AY8910 подтверждает, что драйвер дошёл до отправки. Либо это часть схемы, где AY8910 управляет чем-то связанным с принтером (маловероятно, но возможно).

## Переменные

Драйвер принтера **не имеет собственных переменных** в рабочей области. Всё состояние — в портах и в `SETUP` (выбор интерфейса).

## Хуки

| Адрес | Имя | Когда вызывается |
|-------|-----|------------------|
| `0FDDBH` | `XFDDB` | LPTOUT hook — в начале `LPTOUT` |

---

## Ограничения

1. **Только параллельный порт.** `LPTOUT` работает с Centronics через `0F6xxH`. Последовательный вывод, вероятно, шёл через `COM_OUT` (отсутствует).
2. **`Ctrl+C` отправляет `CR`.** При прерывании `LPTOUT` отправляет `0DH` (CR), чтобы принтер не остался в середине строки.
3. **Звук при каждой отправке.** `LPTOUT_3` пишет `0FH` в AY8910 — это может быть нежелательно, если вы используете AY8910 для музыки. Вероятно, это диагностический сигнал, который можно отключить, заменив `WR_PSG` на `NOP`/`RET`.
4. **Нет проверки ошибок.** Драйвер не читает `ERROR`/`PE`/`SLCT` — только `BUSY`.
