# 08-errata.md — Известные проблемы комплекта

## Назначение

Этот документ фиксирует всё, что **отсутствует, обрезано или не подключено** в предоставленном комплекте исходников. Если вы пытаетесь собрать прошивку — начните отсюда. Если вы изучаете код — здесь перечислены места, где не хватает контекста.

---

## 1. `BIOS.DRV` — обрезан на `CTS_INT`

Файл обрывается на комментарии `; Прерывание по готовности пер◀` (должно быть «…передачи»). Отсутствуют **7 символов**, на которые есть ссылки в видимом коде:

| Символ | Кто ссылается | Назначение | Документ |
|--------|---------------|-----------|----------|
| `TEST_TX` | `CTS_INT` (`CALL TEST_TX`) | проверка XON/XOFF / готовности передачи | [04-serial.md](04-serial.md) |
| `RX_INT` | `COM_INI` (`LD (XFDAE+1),HL`) | обработчик RxRDY (приём байта в `RX_BUF`) | [04-serial.md](04-serial.md) |
| `TX_INT` | `COM_INI` (`LD (XFDB3+1),HL`) | обработчик TxRDY (выдача байта из `TX_BUF`) | [04-serial.md](04-serial.md) |
| `COM_OUT_ST` | `BIOS.MAC` `L0156` | проверка готовности выхода RS-232 | [04-serial.md](04-serial.md) |
| `COM_OUT` | `BIOS.MAC` `L0159` | вывод байта в RS-232 | [04-serial.md](04-serial.md) |
| `COM_IN_ST` | `BIOS.MAC` `L015C` | проверка готовности входа RS-232 | [04-serial.md](04-serial.md) |
| `COM_IN` | `BIOS.MAC` `L015F` | приём байта из RS-232 | [04-serial.md](04-serial.md) |

**Последствие:** `BIOS.MAC` **не линкуется**. Векторы `L0156`–`L015F` ссылаются на неопределённые символы.

**Как восстановить:**
1. Дизассемблировать готовую прошивку по адресам `XFDB3` (TxRDY), `XFDAE` (RxRDY) и векторам `L0156`–`L015F`.
2. Или написать свои реализации по описанию в [04-serial.md](04-serial.md) (реконструкция по контексту `COM_INI` и `CTS_INT`).

---

## 2. Внешние ресурсы

| Символ | Где объявлен | Статус | Что делать |
|--------|--------------|--------|-----------|
| `ALEST` | `EXTRN` в `BIOS.MAC`, `ROM.MAC` | **отсутствует** (знакогенератор) | Извлечь из готовой прошивки или найти отдельный файл шрифта |
| `DATA` | `EXTRN` в `ROM.MAC` | **отсутствует** (заставка) | Извлечь из готовой прошивки или нарисовать свою |
| `COLORS` | `BIOS.MAC`: `PALTAB EQU 0FE7FH; DS 10H,COLORS` | **не определён** | Заменить на `0` — `PALTAB` всё равно инициализируется через `PAL_INIT` из `PALINITAB` |

**Последствие:** без `ALEST` не работает вывод символов (`SYMBOL2` читает шрифт через `PGTADR`). Без `DATA` не работает заставка при холодной перезагрузке (`RE_BOOT`).

---

## 3. `BIOS.GRP` и `BIOS.SPR` не подключены к `BIOS.MAC`

В текущем `BIOS.MAC` есть только:
```asm
INCLUDE BIOS.SCR
INCLUDE BIOS.DRV
```

`BIOS.GRP` и `BIOS.SPR` в комплекте есть, но **не подключены**. Это библиотеки, которые линковались отдельно (или подключались в другой версии главного модуля).

**Последствие:** функции `PUT_PIXEL`, `GET_PIXEL`, `GR_LINE`, `HORIZ_LINE`, `VERT_LINE`, `FILL_RECTANGLE`, `DRAW_SPRITE`, `UNDRAW_SPRITE`, `COPY_M_TO_V`, `COPY_V_TO_M`, `COPY_V_TO_V` **недоступны** через векторы BIOS. Векторы `L0162` (`FMESSXY`) и `L0165` (`INVERT`) есть, но это не графика.

**Как исправить:** добавить в `BIOS.MAC` перед `END`:
```asm
INCLUDE BIOS.GRP
INCLUDE BIOS.SPR
```

**Порядок важен:** `BIOS.SPR` использует `GR_GET_ADR`, `WR_PIX`, `NEXT_LINE`, `TAB_CONV_*` из `BIOS.GRP`, поэтому `BIOS.GRP` должен идти первым.

**Дополнительно:** `BIOS.GRP` использует `DIVISION`, которая определена в нём же, и `WR_PSG`, `CPHLDE`, `CPHLBC` из `BIOS.MAC`. `BIOS.SPR` использует `BUFSYM1`/`BUFSYM2` из `BIOS.SCR`. Значит, порядок такой:
```
BIOS.SCR
BIOS.DRV
BIOS.GRP
BIOS.SPR
```

## 4. `COLORS` не определён

В `BIOS.MAC`:
```asm
PALTAB EQU 0FE7FH; DS 10H,COLORS
```

`COLORS` нигде не определён — ни в `BIOS.SCR`, ни в `BIOS.GRP`, ни в `BIOS.DRV`. Это, скорее всего, артефакт: `PALTAB` инициализируется через `PAL_INIT` из `PALINITAB`, поэтому `COLORS` можно заменить на `0`.

**Как исправить:** в `BIOS.MAC` заменить строку на:
```asm
PALTAB EQU 0FE7FH; DS 10H,0
```

---

## 5. `ROM.MAC` — упрощённая `SNSMAT` без `DI/EI`

`ROM.MAC` содержит собственную `SNSMAT` (для загрузчика), которая **не** делает `DI`/`EI` в начале/конце. Версия в `BIOS.MAC` делает. Для загрузчика это допустимо (прерывания ещё не включены), но **не эквивалентно** `BIOS.MAC`-версии. Если вы копируете `SNSMAT` из `ROM.MAC` в свой код — добавьте `DI`/`EI` сами.

---

## 6. `MOUSE1.MAC` — отладочный вывод в порты `0FAD0H/0FAD2H`

Пример `MOUSE1.MAC` пишет координаты мыши в порты `0FAD0H`/`0FAD2H`. Это, вероятно, отладочный вывод (ЦАП/индикатор), а не штатная периферия. В реальном коде эти порты использовать не нужно.

---

## 7. `BIOS.DRV` — `LPTOUT_3` пишет в AY8910

`LPTOUT_3` при каждой отправке байта на принтер пишет `0FH` в AY8910 (регистр `0FH`). Это может быть диагностический сигнал, но он **мешает**, если вы используете AY8910 для музыки. Если принтер не нужен — не вызывайте `LPTOUT`. Если нужен — можно заменить `CALL WR_PSG` на `NOP`/`RET`.

---

## 8. `BIOS.DRV` — `CTS_INT` не линкуется

`CTS_INT` содержит `CALL TEST_TX`, но `TEST_TX` отсутствует. Даже если вы восстановите `COM_OUT`/`COM_IN`, `CTS_INT` всё равно не соберётся без `TEST_TX`. См. пункт 1.

---

## 9. Что **есть** и работает

Чтобы не создавать ложного впечатления, перечислим, что в комплекте **полностью присутствует**:

| Компонент | Статус |
|-----------|--------|
| `BIOS.MAC` (векторы, `INIT`, `INT38`, слоты, `WR_PSG`/`RD_PSG`, `WR_CLOCK`/`RD_CLOCK`, `WR_CRT`/`RD_CRT`, `WAIT`, `CHGRUS`, `SNSMAT`, таймер) | ✅ полный |
| `BIOS.SCR` (экран, курсор, ESC, ролик, палитра, BEEP) | ✅ полный |
| `BIOS.DRV` — клавиатура (`KEY_INIT`, `KEY_SCAN`, `KEY_SCN`, `READ_KEY`, `INPUT`, `INKEY`, `TEST_KEY`, `BREAK`, таблицы, `SET_*/GET_*`) | ✅ полный |
| `BIOS.DRV` — мышь (`MOUS_INIT/ON/OFF`, `GET_MOUS`, `SET_MOUS`, `SET_MLIM`, `SET_MSCAL`, `MOUS_INT`, `MOUS_ERR`) | ✅ полный |
| `BIOS.DRV` — принтер (`LPTOUT`, `LPTSTT`) | ✅ полный |
| `BIOS.DRV` — RS-232 (`COM_INI`, `RS_ERR`, `CTS_INT`) | ⚠️ частично (нет хвоста) |
| `BIOS.GRP` (графика) | ✅ полный |
| `BIOS.SPR` (спрайты) | ✅ полный |
| `ROM.MAC` (загрузчик, `SETUP`, НГМД i8272) | ✅ полный |
| `TKEY1.MAC`, `KEY.MAC`, `MOUSE1.MAC` (примеры) | ✅ полные |

## 10. Итог

**Для изучения кода** комплекта достаточно. Все драйверы, кроме хвоста RS-232, представлены полностью, с комментариями и примерами.

**Для сборки прошивки** нужно:
1. Восстановить 7 символов RS-232 (пункт 1).
2. Найти или извлечь `ALEST` и `DATA` (пункт 2).
3. Заменить `COLORS` на `0` (пункт 4).
4. Добавить `INCLUDE BIOS.GRP` и `INCLUDE BIOS.SPR` в `BIOS.MAC` (пункт 3).

После этого `BIOS.MAC` должен собраться (при наличии ассемблера Z80, поддерживающего `.PHASE`/`.DEPHASE`/`INCLUDE`/`EXTRN` — например, `ZSM`, `TASM`, `sjasmplus`).
