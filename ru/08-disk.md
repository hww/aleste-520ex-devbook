# 07. Дисковод

Дисковод в Aleste — это контроллер 765 FDC, тот же самый,
что стоял в Amstrad CPC 6128 и в куче других машин (PC,
MSX, и так далее). Микросхема стандартная, документация
на неё есть в открытом доступе, и она хорошо изучена.

В этом разделе — самое необходимое: что за контроллер,
какие порты, как прочитать сектор. Полное описание
всех команд 765 FDC — это отдельная большая тема, здесь
её не будет.

## Что за контроллер

**NEC µPD765** (или его аналог) — контроллер гибких дисков.
Умеет читать и писать сектора, форматировать дорожки,
искать дорожку, позиционировать головку.

В Aleste он подключён к дисководу 3.5", 80 дорожек,
720 КБ. Может быть до двух дисководов.

Контроллер имеет два режима работы: **режим исполнения**
(execution mode) и **режим результата** (result mode).
Команды посылаются в режиме исполнения, результаты
читаются в режиме результата. Переключение между
режимами — автоматическое, по состоянию контроллера.

## Порты

| Порт    | Что             | RW |
|---------|-----------------|----|
| `#FA7E` | Мотор дисковода | W  |
| `#FB7E` | Статус (Main Status Register) | R  |
| `#FB7F` | Данные (Data Register)        | RW |

<!-- FIX: уточнено, что #FB7E — только чтение (Main Status Register),
     а данные/команды/параметры/результаты идут через #FB7F. -->

**`#FA7E`** — управление мотором. Бит 0: 0 — мотор выключен,
1 — включён.

**`#FB7E`** — Main Status Register (только чтение). Показывает
состояние контроллера: готов ли он к обмену, направление
обмена, режим, занятость, занятость дисководов.

**`#FB7F`** — Data Register. Через него идёт вся информация:
команды, параметры, результаты, данные секторов.

## Как это работает

Общая схема такая.

1. Включаешь мотор (`#FA7E`).
2. Ждёшь, пока контроллер готов (RQM=1, DIO в нужном
   состоянии — см. ниже).
3. Посылаешь команду через `#FB7F`.
4. Посылаешь параметры команды (тоже через `#FB7F`).
5. Контроллер выполняет команду.
6. Читаешь результат (через `#FB7F`).
7. Читаешь или пишешь данные сектора (если команда
   была read/write).

Каждый шаг требует проверки статуса — контроллер не
мгновенный, и если писать в него, когда он не готов,
данные потеряются.

## Регистр статуса (Main Status Register)

Регистр `#FB7E` возвращает байт с **фиксированным**
значением битов (это Main Status Register 765 FDC, его
биты не меняют смысл в зависимости от режима):

| Бит | Что                                                           |
|-----|---------------------------------------------------------------|
| 7   | RQM — Request for Master (готовность к обмену)                |
| 6   | DIO — Data Input/Output: 0 — от процессора, 1 — к процессору  |
| 5   | NDMA — Non-DMA mode: 1 — режим исполнения, 0 — режим результата |
| 4   | CB — Controller Busy (контроллер занят)                       |
| 3–0 | D0B–D3B — Drive Busy (занятость дисководов 0–3)               |

<!-- FIX: исправлено. Было «биты означают разное в зависимости от режима» —
     неверно, Main Status Register имеет фиксированные биты.
     Было «биты 3–0 — код ошибки» — неверно, это Drive Busy.
     Код ошибки читается из Result Register (ST0–ST3), а не из статуса. -->

**RQM (бит 7)** — самый важный. Пока он равен 0,
контроллер занят и не готов к обмену. Нужно ждать,
пока он станет 1.

**DIO (бит 6)** — направление. Если 0 — контроллер
ждёт данные от процессора (можно писать в `#FB7F`).
Если 1 — контроллер отдаёт данные (можно читать
из `#FB7F`).

**NDMA (бит 5)** — режим. 1 — режим исполнения
(команды), 0 — режим результата (результаты).

**CB (бит 4)** — контроллер занят выполнением команды.

**D0B–D3B (биты 3–0)** — занятость дисководов 0–3
(1 = дисковод занят). Не код ошибки.

## Пример: дождаться готовности

Перед любым обменом нужно дождаться, пока контроллер
готов. Вот простая процедура.

```asm
; Ждём, пока контроллер готов к обмену (RQM=1)
WaitFDC:
    LD BC, #FB7E
    IN A, (C)          ; читаем Main Status Register
    BIT 7, A           ; проверяем RQM
    JR Z, WaitFDC      ; если 0 — ждём дальше
    RET
```

<!-- FIX: исправлен синтаксис IN (было IN A,(#FB7E) — не собирается). -->

После этого можно писать или читать `#FB7F`. **Но** для
корректного обмена нужно ещё проверить DIO: если
собираешься писать — DIO должен быть 0; если читать —
DIO должен быть 1. `WaitFDC` проверяет только RQM; для
полной проверки добавь `BIT 6,A` и сравни с ожидаемым
направлением.

## Пример: прочитать сектор

Допустим, мы хотим прочитать сектор с диска. Это
команда READ DATA.

Параметры команды READ DATA (8 байт после кода команды):

- **HD/US** — головка (бит 2) и номер дисковода (биты 1–0).
- **C** — номер цилиндра (дорожки).
- **H** — номер головки (0/1).
- **R** — номер сектора (1..9 для 720 КБ).
- **N** — размер сектора (2 = 512 байт; размер = 128 × 2^N).
- **EOT** — номер последнего сектора (для одного сектора = R).
- **GPL** — длина промежутка (gap; обычно `0x2A` для 3.5").
- **DTL** — длина данных (обычно `0xFF`, если читать до конца сектора).

<!-- FIX: уточнено, что первый параметр — HD/US (головка + номер дисковода),
     а не «дисковод и головка». Также добавлена формула размера сектора. -->

Полный пример — это много кода. Вот скелет.

```asm
; Предположим, параметры уже подготовлены
; в переменных: drive, track, head, sector

    ; Включаем мотор
    LD BC, #FA7E
    LD A, 1
    OUT (C), A

    ; Ждём готовности
    CALL WaitFDC

    ; Посылаем команду READ DATA
    ; Код команды: 0x06 (read data, MFM, single-sector)
    ;            0x66 (read data, MFM, multi-sector)
    ; В ROM.MAC используется 0x66 (multi-sector).
    LD BC, #FB7F
    LD A, 0x06
    OUT (C), A
    CALL WaitFDC

    ; Посылаем параметры
    LD A, (drive)      ; HD/US: биты 1-0 = unit, бит 2 = head
    OUT (C), A
    CALL WaitFDC

    LD A, (track)      ; C — цилиндр
    OUT (C), A
    CALL WaitFDC

    LD A, (head)       ; H — головка
    OUT (C), A
    CALL WaitFDC

    LD A, (sector)     ; R — сектор
    OUT (C), A
    CALL WaitFDC

    LD A, 2            ; N — размер сектора (512 байт)
    OUT (C), A
    CALL WaitFDC

    LD A, (sector)     ; EOT — последний сектор (читаем один)
    OUT (C), A
    CALL WaitFDC

    LD A, 0x2A         ; GPL — gap length (обычно 0x2A для 3.5")
    OUT (C), A
    CALL WaitFDC

    LD A, 0xFF         ; DTL — длина данных
    OUT (C), A
    CALL WaitFDC

    ; Теперь читаем результат (7 байт: ST0, ST1, ST2, C, H, R, N)
    LD B, 7
    LD HL, ResultBuf
ReadResult:
    CALL WaitFDC
    LD BC, #FB7F
    IN A, (C)
    LD (HL), A
    INC HL
    DJNZ ReadResult

    ; Проверяем статус: ST0 биты 7-6 = IC (00 = normal, 01 = abnormal)
    LD A, (ResultBuf)  ; ST0
    AND 0xC0           ; биты 7,6 — IC
    JR NZ, ReadError

    ; Читаем данные сектора (512 байт)
    LD B, 0            ; 256 байт за раз, потом ещё 256
    LD HL, SectorBuf
ReadData1:
    CALL WaitFDC
    LD BC, #FB7F
    IN A, (C)
    LD (HL), A
    INC HL
    DJNZ ReadData1

    LD B, 0
ReadData2:
    CALL WaitFDC
    LD BC, #FB7F
    IN A, (C)
    LD (HL), A
    INC HL
    DJNZ ReadData2

    ; Выключаем мотор
    LD BC, #FA7E
    XOR A
    OUT (C), A
    RET
```

     Уточнён код команды: 0x06 — single-sector, 0x66 — multi-sector
     (в ROM.MAC используется 0x66).
     Уточнено, что результат — 7 байт (ST0, ST1, ST2, C, H, R, N).

Это длинно и муторно, но так работает железо. В реальной

## Что делает BIOS

Если не хочешь возиться с 765 FDC напрямую — используй
BIOS или AMSDOS. AMSDOS предоставляет функции работы
с файлами: открыть, прочитать, записать, закрыть. Это
гораздо удобнее, чем дёргать сектора вручную.

Стандартный путь для работы с диском в CPC-мире — через
AMSDOS. Он берёт на себя всю низкоуровневую работу.

Если ты пишешь свою ОС или загрузчик — придётся работать
с 765 FDC напрямую. Но для большинства задач AMSDOS
достаточно. Пример прямой работы с FDC — в `ROM.MAC`
(`BOOT`, `INPFILE`, `DSKIO`, `FDCRD`, `RD1SEC`).

## Формат диска

Aleste использует диски 3.5", 720 КБ. Это стандартный
формат для CPC-совместимых машин.

Параметры:

- 80 дорожек (цилиндров).
- 2 стороны.
- 9 секторов на дорожку.
- 512 байт на сектор.

Итого: 80 * 2 * 9 * 512 = 737280 байт ≈ 720 КБ.

**Форматы AMSDOS и MSX-DOS несовместимы** по расположению
каталога/FAT, хотя геометрия (80×2×9×512) может совпадать.
Диск, отформатированный под AMSDOS, не прочитается в
MSX-DOS, и наоборот.

## Два дисковода

Aleste поддерживает до двух дисководов. Второй дисковод
подключается к тому же разъёму, что и первый, но
выбирается отдельным сигналом.

В SETUP можно настроить, сколько дисководов подключено
и как они используются. Если второго дисковода нет,
можно эмулировать его логически — система будет
считать, что диск B: существует, но физически
обращаться к A:.

## Защита от записи

На дискете есть переключатель защиты от записи.
Если он установлен, контроллер не сможет писать
на диск. Это аппаратная защита, программно её
обойти нельзя.

При попытке записи на защищённый диск контроллер
вернёт ошибку (ST1 бит 6 = WP — Write Protected).
Программа должна её обработать.

## Ошибки

765 FDC возвращает результат команды в виде 7 байт:
**ST0, ST1, ST2, C, H, R, N**.

- **ST0** (первый байт): биты 7–6 = IC (Interrupt Code:
  00 = normal, 01 = abnormal), бит 5 = SE (Seek End),
  бит 4 = EC (Equipment Check), бит 3 = NR (Not Ready),
  бит 2 = HD (Head), биты 1–0 = US (Unit Select).
- **ST1** (второй байт): бит 0 = MA (Missing Address Mark),
  бит 1 = NW (Not Writable), бит 2 = ND (No Data),
  бит 3 = OR (Over Run), бит 4 = DE (Data Error / CRC),
  бит 5 = EN (End of Cylinder), бит 6 = WP (Write Protected).
- **ST2** (третий байт): бит 0 = CM (Control Mark),
  бит 1 = DD (Data Error in Data Field), бит 2 = WC
  (Wrong Cylinder), бит 3 = SH (Scan Equal Hit),
  бит 4 = SN (Scan Not Satisfied), бит 5 = BC
  (Bad Cylinder).

<!-- FIX: исправлено. Было «код ошибки — биты 7,6 результата,

Основные ошибки:

- **Нет диска** — ST0 бит 3 = NR (Not Ready), или ST3 бит 2 = Ready.
- **Не готов** — ST0 бит 3 = NR.
- **Ошибка данных** — ST1 бит 4 = DE (CRC Error).
- **Защита от записи** — ST1 бит 6 = WP.
- **Сектор не найден** — ST1 бит 2 = ND (No Data).

## Практические советы

**Используй AMSDOS.** Не пиши свой драйвер диска,
если не хочешь потратить недели. AMSDOS работает,
отлажен, и его достаточно для большинства задач.

**Жди RQM (и DIO).** Всегда. Контроллер 765 FDC не терпит
спешки. Если писать в него, когда он не готов —
данные потеряются, и ты получишь непонятную ошибку.
Проверяй не только RQM (бит 7), но и DIO (бит 6):
для записи DIO должен быть 0, для чтения — 1.

<!-- FIX: добавлено про DIO. -->

**Не забывай выключать мотор.** Мотор дисковода
не должен крутиться постоянно. Включай перед
операцией, выключай после.

**Проверяй ошибки.** 765 FDC возвращает коды ошибок
в ST0/ST1/ST2. Если их не проверять, программа
будет вести себя странно.

**Помни про формат.** AMSDOS и MSX-DOS — разные
форматы. Не путай.
