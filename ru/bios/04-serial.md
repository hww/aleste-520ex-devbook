# 04-serial.md — Драйвер последовательного порта / RS-232 (BIOS.DRV)

## Назначение

Управляет встроенным USART **KR580WW51A** (клон Intel 8251) . Порт используется как для связи с внешними устройствами, так и для последовательной мыши. Тактирование скорости передачи обеспечивает таймер **KR580WI53** (8253) .

**Критическое ограничение комплекта:** хвост драйвера (`COM_OUT`, `COM_IN`, `COM_OUT_ST`, `COM_IN_ST`, `RX_INT`, `TX_INT`, `TEST_TX`) в предоставленных исходниках **отсутствует**. Векторы `L0156`–`L015F` ссылаются на неопределённые символы. Ниже описано, что эти вызовы **должны** делать, исходя из видимой части `COM_INI`, `CTS_INT` и архитектуры 8251. Это **реконструкция**, а не документация по реальному коду.

**Исходник:** `BIOS.DRV` (обрезан).

---

## Инициализация

### `COM_INI` (`L0153`) — **есть в комплекте**

Настраивает ВВ51 и ВИ53. Устанавливает обработчики прерываний RS-232 (`XFDA4`, `XFDA9`, `XFDAE`, `XFDB3`) и сбрасывает буферы.

```
Вход:  A = формат кадра:
           bit2-3: длина символа (00=5, 01=6, 10=7, 11=8 бит)
           bit4-5: чётность (00=нет, 01=нечёт, 11=чёт)
           bit6-7: стоп-биты (01=1, 10=1.5, 11=2)
       B = скорость: 0=300, 1=600, 2=1200, 3=2400 бод
Выход: —
Изменяет: все регистры
```

**Что делает:** записывает `Mode Instruction` в регистр управления 8251 (порт `0EFxxH`) , настраивает каналы A и B таймера 8253 для генерации TxC/RxC, записывает `Command Instruction` (`TxEN=1, RxEN=1, DTR=1`). Если `A` bit0 = 0, режим `RS_MODE` = RTS/CTS; иначе XON/XOFF.

**Пример:**
```asm
    LD   A,4EH      ; 8 бит, без чётности, 1 стоп-бит
    LD   B,2        ; 1200 бод
    CALL L0153      ; COM_INI
```

## Передача (реконструкция)

### `COM_OUT_ST` (`L0156`) — **отсутствует**

Проверка готовности к передаче. Должна читать `Status Register` 8251 (порт `0EFxxH`) и проверять бит 0 (`TxReady` / `DB Buffer Empty`) .

```
Вход:  —
Выход: ZF=1 если можно писать (буфер пуст)
       ZF=0 если занят
Изменяет: AF
```

### `COM_OUT` (`L0159`) — **отсутствует**

Вывод байта. Должна либо писать напрямую в `Data Register` (порт `0EExxH`), если буфер пуст, либо класть байт в `TX_BUF` и ждать прерывания `TxRDY`.

```
Вход:  A = байт для передачи
Выход: CF=1 если буфер полон (байт не отправлен)
       CF=0 если принят
Изменяет: AF
```

**Логика по контексту:** в `COM_INI` есть `TX_HEAD`/`TX_TAIL` (указатели в `TX_BUF`), а `CTS_INT` читает `TX_HEAD` и пишет в порт. Значит, `COM_OUT` скорее всего **буферизованный**: байт кладётся в `TX_BUF`, продвигается `TX_TAIL`, а реальная передача происходит в `TX_INT` по прерыванию `TxRDY`. `CF=1` — если буфер переполнен (`TX_TAIL` догнал `TX_HEAD`).

## Приём (реконструкция)

### `COM_IN_ST` (`L015C`) — **отсутствует**

Проверка наличия принятых данных. Должна читать `Status Register` 8251 и проверять бит 1 (`RxReady`) , либо сравнивать `RX_HEAD` и `RX_TAIL` (если приём буферизован через `RX_INT`).

```
Вход:  —
Выход: ZF=1 если есть данные для чтения
       ZF=0 если данных нет
Изменяет: AF
```

### `COM_IN` (`L015F`) — **отсутствует**

Приём байта. Должна либо читать `Data Register` напрямую, либо брать байт из `RX_BUF` по `RX_TAIL`. Также проверяет `Ctrl+C` через `BREAK` (по аналогии с `LPTOUT`).

```
Вход:  —
Выход: A = принятый байт
       CF=1 если нажат Ctrl+C (прерывание)
Изменяет: AF
```

**Логика по контексту:** `RX_BUF` (40h байт), `RX_HEAD`/`RX_TAIL` инициализируются в `COM_INI`. `RX_INT` (отсутствует) должен принимать байт по прерыванию `RxRDY` и класть в `RX_BUF`, продвигая `RX_HEAD`. `COM_IN` читает из `RX_BUF` по `RX_TAIL`.

## Обработчики прерываний (частично есть)

### `RS_ERR` — **есть**

Обработчик ошибки (вектор `XFDA4`). Устанавливает бит сброса ошибки (`RS_COM |= 10H`) и записывает обратно в порт управления.

### `CTS_INT` — **есть (обрезан на вызове `TEST_TX`)**

Обработчик CTS (вектор `XFDA9`). В режиме RTS/CTS проверяет линию CTS и, если есть данные в `TX_BUF`, отправляет их напрямую в порт. **Не линкуется** из-за отсутствия `TEST_TX`.

### `RX_INT` — **отсутствует**

Должен читать `Data Register` по прерыванию `RxRDY`, класть байт в `RX_BUF` по `RX_HEAD`, обрабатывать XON/XOFF (флаги `RX_XOFF`/`TX_XOFF`), проверять переполнение буфера и вызывать хук `XFDAE`.

### `TX_INT` — **отсутствует**

Должен брать байт из `TX_BUF` по `TX_HEAD` и писать в `Data Register` по прерыванию `TxRDY`, продвигая `TX_HEAD`. В режиме XON/XOFF проверяет `TX_XOFF` (если установлен — не передавать).

### `TEST_TX` — **отсутствует**

Вызывается из `CTS_INT`. Вероятно, проверяет флаг `TX_XOFF` или готовность к передаче в режиме XON/XOFF.

## Переменные драйвера

| Адрес | Имя | Назначение |
|-------|-----|-----------|
| `0FF00H` | `RX_BUF` | Буфер приёма (40H байт) |
| `0FF40H` | `TX_BUF` | Буфер передачи (40H байт) |
| `0FF80H` | `RX_HEAD` | Указатель записи в `RX_BUF` |
| `0FF82H` | `RX_TAIL` | Указатель чтения из `RX_BUF` |
| `0FF84H` | `TX_HEAD` | Указатель чтения из `TX_BUF` |
| `0FF86H` | `TX_TAIL` | Указатель записи в `TX_BUF` |
| `0FF88H` | `RS_COM` | Теневой регистр команды 8251 |
| `0FF89H` | `RS_STAT` | Теневой регистр статуса 8251 |
| `0FF8AH` | `RS_MODE` | `0` = RTS/CTS, `1` = XON/XOFF |
| `0FF8BH` | `RX_XOFF` | Флаг XOFF (приём) |
| `0FF8CH` | `TX_XOFF` | Флаг XOFF (передача) |

## Порты

| Порт | Назначение |
|------|-----------|
| `0EExxH` | Data Register 8251 (чтение/запись) |
| `0EFxxH` | Control/Status Register 8251 (запись/чтение)  |

---

## Ограничения

1. **Мышь и RS-232 несовместимы.** Оба используют один USART и одни буферы. Для RS-232 сначала вызовите `MOUS_OFF`.
2. **Хвост драйвера отсутствует.** Без восстановления `COM_OUT`/`COM_IN`/`COM_OUT_ST`/`COM_IN_ST`/`RX_INT`/`TX_INT`/`TEST_TX` сборка невозможна.
3. **Скорость только до 2400 бод** (по `RATE_TAB`: 300/600/1200/2400).
