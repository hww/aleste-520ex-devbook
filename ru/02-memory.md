# 02. Память

В первом разделе мы разобрались, что такое банки, страницы и зачем
нужен маппер. Теперь — конкретика. Как именно переключать банки
из кода, чем отличается CPC-банкинг от расширенного маппера Aleste,
и что делать с ROM.

Раздел длинный, потому что тема центральная. Но всё по делу.

## Ещё раз: банки и страницы

Напомню терминологию, чтобы не путаться.

**Физическая память** — это 512 КБ, которые реально стоят в машине.
Они нарезаны на 32 банка по 16 КБ. У каждого банка есть номер:
0–31. Эти номера не меняются никогда.

**Логические страницы** — это четыре окна, которые видит Z80:
страница 0 (0x0000–0x3FFF), страница 1 (0x4000–0x7FFF),
страница 2 (0x8000–0xBFFF), страница 3 (0xC000–0xFFFF).

**Маппер** — устройство, которое решает, какой физический банк
стоит в каждой логической странице прямо сейчас.

Меняешь содержимое маппера — меняется то, что видит процессор
по соответствующему адресу. Сами данные в банках при этом
никуда не деваются, они ждут, когда их снова подставят в окно.

## Два способа управлять памятью

У Aleste есть два режима банкинга, и они переключаются флагом
MAPMOD (порт `#FABF`, бит 2).

- **MAPMOD = 0** — CPC-банкинг. Совместим с Amstrad CPC 6128.
- **MAPMOD = 1** — расширенный маппер Aleste. Даёт доступ ко всем
  512 КБ и всем 32 банкам.

Важно понять: это не «старый способ» и «новый способ». Это два
разных инструмента для разных задач. CPC-банкинг нужен, чтобы
работал старый софт. Расширенный маппер нужен, чтобы писать
новый софт, использующий всю память.

Можно переключаться между ними на ходу, но нужно понимать,
что при переключении меняется и поведение памяти, и поведение
палитры (см. раздел про экран).

### Важное предупреждение: MAPMOD переставляет блоки памяти

Тут есть тонкость, о которой в мануалах почти не пишут,
а она критична.

Переключение MAPMOD — это не просто смена флага. Это
**перестановка адресных линий**: A14 и A11 меняются
местами.

Что это значит. Если код, который выполняет переключение
MAPMOD, находится в области, зависящей от этих линий —
процессор после переключения уйдёт не туда. Программа
упадёт или поведёт себя непредсказуемо.

**Правило:** код переключения MAPMOD должен лежать там,
где A14 и A11 равны — тогда перестановка ничего не меняет,
и код продолжит работать. Обычно это ROM: он не участвует
в перестановке банков и всегда виден по своим адресам.

Пример: если ты переключаешь MAPMOD из RAM по адресу
0x4000, и этот адрес зависит от A14 — после переключения
процессор продолжит выполнение уже из другого банка.
Твой код просто исчезнет из виду.

Поэтому BIOS делает переключение режима сам, из ROM.
Если тебе нужно переключить MAPMOD из своей программы —
сделай это через вызов BIOS или помести код переключения
в ROM.

Точная схема перестановки адресов при смене MAPMOD —
в презентации [Aleste — больше, чем просто
версия Amstrad CPC](../library/aleste-more-than-amstrad-cpc-demodulation-2021.pdf).

## CPC-банкинг (MAPMOD = 0)

Это схема от Amstrad CPC 6128. Она рассчитана на 128 КБ памяти
(8 банков), но Aleste умеет её расширять через дополнительный
порт.

### Порт #7F00: регистр конфигурации RAM

Порт `#7F00` — это регистр, который управляет тем, какие банки
стоят в страницах 1, 2 и 3. Страница 0 им не управляется,
о ней отдельно.

Формат записываемого байта:

```
%1M2M1M0
```

Здесь:
- Бит 7 всегда равен 1. Это признак, что мы пишем именно
  в регистр конфигурации RAM, а не в Gate Array (они делят
  один адрес, подробности в разделе про порты).
- Биты 6–5 — **M2**, номер банка для страницы 3 (0xC000–0xFFFF).
- Биты 4–3 — **M1**, номер банка для страницы 2 (0x8000–0xBFFF).
- Биты 2–1 — **M0**, номер банка для страницы 1 (0x4000–0x7FFF).
- Бит 0 не используется.

Значения M0, M1, M2 расшифровываются так:

| Значение | Что означает |
|----------|--------------|
| 00 | Банк 0 |
| 01 | Банк 1 |
| 10 | Банк 2 |
| 11 | Расширенный банк (номер задаётся через порт #DF00) |

Первые три варианта — это базовые 64 КБ, которые есть на любом
CPC. Четвёртый вариант — механизм расширения: он говорит «возьми
номер банка не из этого регистра, а из другого порта».

### Порт #DF00: расширенный банк и ROM

Порт `#DF00` — многофункциональный. Его значение зависит от того,
что ты в него пишешь.

Формат записываемого байта:

```
%R-BBBBBB
```

Здесь:
- Бит 7 — **R**. Выбор режима ROM: 0 — внутренние ROM (BASIC, BIOS),
  1 — внешние ROM-картриджи.
- Бит 6 не используется.
- Биты 5–0 — **B**. Номер банка, от 0 до 63.

Когда `B` интерпретируется как номер банка RAM: если в порту
`#7F00` для какой-то страницы выставлено `11`, то именно это
значение `B` и будет номером физического банка, который встанет
в эту страницу.

Когда `B` интерпретируется как номер ROM: если бит `R` равен 1,
то `B` — номер банка внешнего ROM-картриджа, который встанет
в страницу 0 (0x0000–0x3FFF).

### Пример: поставить банк 5 в страницу 1

Допустим, мы хотим, чтобы по адресам 0x4000–0x7FFF был виден
физический банк 5.

Банк 5 — это «расширенный» банк, потому что базовые — только
0, 1, 2. Значит, для M0 надо выставить `11`, а номер банка
положить в `#DF00`.

```
; Сначала сообщаем, что банк для страницы 1 — расширенный
; M0 = 11, M1 и M2 оставляем как были (допустим, 00 и 00)
LD A, %10000110    ; бит 7 = 1, M2 = 00, M1 = 00, M0 = 11
OUT (#7F00), A

; Теперь кладём номер банка в расширенный регистр
LD A, 5            ; R = 0 (внутренние ROM), B = 5
OUT (#DF00), A
```

После этого по адресам 0x4000–0x7FFF будет виден банк 5.

Замечание: если банк 5 не нужно, а нужен, скажем, банк 1,
то всё проще — можно обойтись без `#DF00`:

```
LD A, %10000010    ; бит 7 = 1, M2 = 00, M1 = 00, M0 = 01
OUT (#7F00), A     ; M0 = 01 значит "банк 1"
```

### Что делает запись нуля в бит 7 порта #7F00

Отдельный случай, о котором стоит знать. Если записать в `#7F00`
байт, у которого бит 7 равен 0, это не команда периферии
(мотор дисковода, сброс FDC и прочее — это делается через PPI,
а не здесь). Это команда **самому мапперу**: сбросить внутренний
регистр в состояние по умолчанию.

По умолчанию выставляется такая карта:

- Страница 1 → банк 1
- Страница 2 → банк 2
- Страница 3 → банк 3

Страница 0 остаётся под управлением бита `R` из порта `#DF00`.

Это удобный способ быстро вернуть память в «безопасное» состояние,
не делая полный сброс машины. Полезно, когда программа, не
умеющая работать с расширенной памятью, ожидает стандартную
карту.

## Расширенный маппер Aleste (MAPMOD = 1)

Когда MAPMOD = 1, вступает в силу другой механизм. Он проще
и мощнее: для каждой логической страницы есть свой отдельный порт.

| Порт | Страница | Адреса |
|------|----------|--------|
| `#7CXX` | Страница 0 | 0x0000–0x3FFF |
| `#7DXX` | Страница 1 | 0x4000–0x7FFF |
| `#7EXX` | Страница 2 | 0x8000–0xBFFF |
| `#7FXX` | Страница 3 | 0xC000–0xFFFF |

Пишешь в порт номер банка — банк встаёт в соответствующую
страницу. Всё. Никаких M0/M1/M2, никаких `#DF00`. Один порт —
одна страница.

### Важное ограничение: биты 6 и 7

Есть тонкость, из-за которой этот маппер легко сломать.

Порты `#7CXX`–`#7FXX` делят адресное пространство с Gate Array
(он тоже слушает `#7FXX`). Чтобы маппер понял, что ты обращаешься
именно к нему, а не к Gate Array, **биты 6 и 7 записываемого
байта должны быть равны 1**.

То есть номер банка — это младшие 6 бит. А два старших бита
всегда `11`.

Полный формат байта:

```
%11BBBBBB
```

Где `BBBBBB` — номер банка (0–31, потому что банков всего 32;
значения 32–63 зарезервированы или не используются).

Пример: поставить банк 10 в страницу 2.

```
LD A, %11001010    ; биты 6,7 = 11, номер банка = 001010 = 10
OUT (#7EXX), A     ; страница 2
```

Заметь: адрес порта — `#7EXX`, где XX любое. Важен только
старший байт.

### Чтение из маппера

Маппер можно не только писать, но и читать. Если сделать `IN`
из порта `#7CXX`, `#7DXX`, `#7EXX` или `#7FXX`, вернётся
номер банка, который сейчас стоит в соответствующей странице.

Это полезно для сохранения/восстановления контекста: перед тем
как временно поменять банк, прочитай текущий, а потом верни
обратно.

```
IN A, (#7EXX)      ; читаем номер банка в странице 2
LD (SavedBank), A  ; сохраняем

; ... тут что-то делаем, меняем банк ...

LD A, (SavedBank)  ; восстанавливаем
OUT (#7EXX), A
```

Обрати внимание: при чтении биты 6 и 7 могут быть не равны 1 —
это зависит от того, как реализовано железо. Не рассчитывай
на них, маскируй младшие 6 бит, если нужно сравнить.

## Что выбрать: CPC-банкинг или расширенный маппер

Практическое правило простое.

**Пишешь новый софт, который использует всю память Aleste** —
включай MAPMOD = 1 и работай через `#7CXX`–`#7FXX`. Это
проще, понятнее и даёт полный доступ к 512 КБ.

**Запускаешь старый CPC-софт, который сам управляет памятью** —
оставляй MAPMOD = 0. Программа сама будет писать в `#7F00`
и `#DF00` так, как ожидает. Ты только не мешай.

**Пишешь что-то, что должно работать и там, и там** —
придётся поддерживать оба режима. Обычно это не нужно; проще
выбрать один и придерживаться его.

## ROM: что это и как переключать

Кроме RAM, у машины есть ROM — постоянная память, которую
процессор видит в старших адресах. В Aleste стоит 64 КБ ROM,
нарезанных на банки по 16 КБ.

Три банка используются:

| Номер | Имя | Что там |
|-------|-----|---------|
| 00h | BASIC | BASIC и часть BIOS |
| 03h | BOOTMENU | Загрузочное меню Aleste |
| 07h | AMSDOS | Дисковая операционная система |

Остальные номера (01, 02, 04, 05, 06, 08 и далее) при выборе
дают тот же BASIC — то есть фактически дублируют банк 00.
Это особенность железа, а не ошибка.

### Порт #DFXX: выбор верхнего ROM-банка

Порт `#DFXX` (тот же, что `#DF00` для расширенного RAM) управляет
тем, какой ROM-банк виден в странице 0 или в старших адресах —
в зависимости от контекста.

Когда ты пишешь в `#DFXX` байт с битом 7 = 0 и номером банка
в младших битах, ты выбираешь ROM-банк. Например:

```
LD A, 3            ; банк 3 = BOOTMENU
OUT (#DFXX), A
```

После этого в области ROM (адреса зависят от того, что включено —
нижний ROM или верхний) будет виден BOOTMENU.

### Включение и выключение ROM

Отдельный вопрос — включён ли ROM вообще. Этим управляют биты
в Gate Array (регистр 2):

- Бит 3 — верхний ROM (Upper ROM) включён/выключен.
- Бит 2 — нижний ROM (Lower ROM) включён/выключен.

Когда ROM выключен, по соответствующим адресам видна RAM.
Это используется, например, чтобы получить доступ к банкам
памяти, которые перекрыты ROM.

Пример: выключить нижний ROM, чтобы получить доступ к RAM
по адресам 0x0000–0x3FFF.

```
; Сначала выбираем регистр 2 Gate Array (биты 7,6 = 10)
LD A, %10000000    ; регистр 2
OUT (#7FXX), A

; Теперь пишем данные в регистр 2
; бит 3 = 1 (верхний ROM включён)
; бит 2 = 0 (нижний ROM выключен)
; биты 1,0 = 00 (режим 0)
LD A, %10001000    ; верхний ROM вкл, нижний ROM выкл
OUT (#7FXX), A
```

Осторожно: выключая нижний ROM, ты убираешь из памяти BIOS.
Если после этого случится прерывание или вызов BIOS — машина
упадёт. Делай это только когда точно знаешь, что делаешь,
и восстанавливай ROM перед возвратом в систему.

## Расширение до 2 МБ: миф или реальность

В мануалах упоминается, что Aleste можно расширить до 2 МБ
памяти. Это спорный вопрос.

С одной стороны, регистровый файл (микросхема D88) теоретически
может хранить два дополнительных бита номера банка, что дало бы
доступ к 64 банкам по 16 КБ = 1 МБ.

С другой стороны, в порту `#7FXX` (расширенный маппер) есть
только один свободный бит — бит 5. Этого хватает на 1 МБ,
но не на 2 МБ.

Вывод: **до 1 МБ — вероятно возможно, 2 МБ — под вопросом**.
На практике большинство Aleste имеют 512 КБ, и этого более
чем достаточно.

## Практические советы

Пара вещей, которые сэкономят время.

**Всегда знай, в каком режиме ты находишься.** MAPMOD = 0 или 1?
От этого зависит всё. Если что-то работает не так, как ожидаешь,
первым делом проверь MAPMOD.

**Не пиши в `#7F00` и `#7FXX` одновременно.** Это один и тот же
адрес, и Gate Array с маппером могут запутаться. Разделяй операции:
сначала работа с CPC-банкингом, потом переключение режима, потом
работа с расширенным маппером.

**Сохраняй контекст перед сменой банка.** Если программа
использует какой-то банк в какой-то странице, а ты временно
ставишь туда другой, верни как было. Иначе получишь трудно
ловимы ошибки.

**Помни, что страница 0 — особенная.** Ею управляет не только
маппер, но и бит `R` из `#DF00`, и биты включения ROM в Gate Array.
Не удивляйся, если запись в `#7CXX` не даёт ожидаемого эффекта —
проверь, включён ли ROM и что выставлено в `#DF00`.
