# 06-graphics.md — Графика нижнего уровня (BIOS.GRP)

## Назначение

Библиотека рисования: точки, линии (Брезенхэм), горизонтальные и вертикальные линии, заполненные прямоугольники, спрайты. Работает во всех четырёх режимах экрана, с режимами записи (`Replace`, `AND`, `OR`, `XOR`, `Transparent`) и клиппингом.

**Важно:** `BIOS.GRP` **не подключён** к `BIOS.MAC` через `INCLUDE` в текущем комплекте. Это отдельная библиотека, которую нужно линковать вручную. Она зависит от `BIOS.SCR` (переменные `SCRMOD`, `PALTAB`, `BUFSYM1`, `BUFSYM2`) и от `BIOS.MAC` (`WR_PSG`, `CPHLDE`, `CPHLBC`, `DIVISION`).

Для CPC-программиста это замена `GRA_*` функций, но с **другим API**: вы заполняете поля в таблице `GR` (`0FC00H`) и вызываете функцию. Никаких регистров с координатами — всё через память.

**Исходник:** `BIOS.GRP` (отдельно).

---

## Таблица параметров `GR` (`0FC00H`)

Все функции читают аргументы из этой таблицы. Заполняйте поля перед вызовом.

| Смещение | Имя | Размер | Назначение |
|----------|-----|--------|-----------|
| `+00` | `_X1` | word | X1 |
| `+02` | `_Y1` | word | Y1 |
| `+04` | `_X2` | word | X2 |
| `+06` | `_Y2` | word | Y2 |
| `+08` | `_DX` | word | Ширина по X |
| `+10` | `_DY` | word | Высота по Y |
| `+12` | `_SRC_PAGE` | byte | Страница-источник |
| `+13` | `_DST_PAGE` | byte | Страница-приёмник |
| `+14` | `_ARG` | byte | Флаги: bit0 X1/Y1 — адрес, bit1 X2/Y2 — адрес, bit2 направление X, bit3 направление Y |
| `+15` | `_WRT_MOD` | byte | Режим записи: 0 Replace, 1 AND, 2 OR, 3 XOR, 4 Transparent, 5 AND, 6 OR, 7 XOR |
| `+16` | `_FG_COLOR` | byte | Цвет переднего плана |
| `+17` | `_BG_COLOR` | byte | Цвет фона |
| `+18` | `_LN_MASK` | word | Маска линии (для пунктира) |
| `+20` | `_PATPTR` | long | Указатель на шаблон заливки |
| `+24` | `_PATMSK` | word | Число линий в шаблоне (0 = нет шаблона) |
| `+26` | `_CLIP` | byte | Флаг клиппинга (0 = нет) |
| `+27` | `_XMN_CLIP` | word | Левая граница клиппинга |
| `+29` | `_YMN_CLIP` | word | Верхняя граница |
| `+31` | `_XMX_CLIP` | word | Правая граница |
| `+33` | `_YMX_CLIP` | word | Нижняя граница |
| `+35` | `_SDBPTR` | long | Указатель на Sprite Definition Block |
| `+39` | `_SPRBUF` | long | Указатель на буфер спрайта |
| `+64` | `WR_PIX` | 3 | Вектор записи пикселя |
| `+67` | `WR_LINE` | 3 | Вектор записи линии |
| `+70` | `GR_PAPER` | byte | Цвет фона (внутренний) |
| `+71` | `GR_INK` | byte | Цвет переднего плана (внутренний) |

## Инициализация

### `GRAPH_INIT`

Очищает таблицу `GR` (обнуляет 0DFH байт), устанавливает `_FG_COLOR=3`, `_WRT_MOD=0` и вызывает `CLS`.

```
Вход:  —
Выход: —
Изменяет: все регистры
```
Вызывать после `SCR_INIT`.

---

### `SET_WRITE_MODE` / `GET_WRITE_MODE`

Установка/чтение режима записи.

```
Вход:  A = режим (0–7)
Выход: (GET) A = режим
```
Устанавливает векторы `WR_PIX` и `WR_LINE` через `JP`-таблицу. Режим 4 — `Transparent` (прозрачный фон, рисуется только `_FG_COLOR`).

---

## Точки

### `PUT_PIXEL`

Рисует точку.

```
Вход:  DE = X, HL = Y, A = цвет (0–15)
       _WRT_MOD, _DST_PAGE
Выход: —
Изменяет: AF
```
Цвет преобразуется через `TRANS_COLOR` в зависимости от режима экрана. Затем `GR_GET_ADR` вычисляет адрес VRAM и маску, и `WR_PIX` записывает байт.

**Пример:**
```asm
    LD   DE,100     ; X=100
    LD   HL,50      ; Y=50
    LD   A,7        ; цвет 7
    CALL PUT_PIXEL
```

---

### `GET_PIXEL`

Читает цвет точки.

```
Вход:  DE = X, HL = Y
       _SRC_PAGE
Выход: A = цвет (0–15)
Изменяет: AF
```

---

## Линии

### `GR_LINE`

Рисует линию по алгоритму Брезенхэма между `(_X1,_Y1)` и `(_X2,_Y2)`.

```
Вход:  _X1, _Y1, _X2, _Y2
       _FG_COLOR, _BG_COLOR, _WRT_MOD, _DST_PAGE, _LN_MASK
Выход: —
Изменяет: все регистры
```
Линия автоматически обрезается по границам клиппинга (`_CLIP`). `_LN_MASK` — маска для пунктира (бит 1 = рисовать, бит 0 = пропустить).

**Пример (диагональ):**
```asm
    LD   HL,0
    LD   (_X1),HL   ; X1=0
    LD   (_Y1),HL   ; Y1=0
    LD   HL,319
    LD   (_X2),HL   ; X2=319
    LD   HL,199
    LD   (_Y2),HL   ; Y2=199
    LD   A,7
    LD   (_FG_COLOR),A
    CALL GR_LINE
```

---

### `HORIZ_LINE`

Горизонтальная линия от `(_X1,_Y1)` до `(_X2,_Y1)` с шаблоном заливки.

```
Вход:  _X1, _X2, _Y1, _FG_COLOR, _BG_COLOR, _WRT_MOD, _DST_PAGE
       _PATPTR, _PATMSK, _CLIP, _XMN_CLIP, _XMX_CLIP, _YMN_CLIP, _YMX_CLIP
Выход: —
```
Если `_PATMSK=0`, линия сплошная. Иначе `_PATPTR` указывает на массив слов-шаблонов, `_PATMSK` — число строк в шаблоне.

---

### `VERT_LINE`

Вертикальная линия от `(_X1,_Y1)` до `(_X1,_Y2)`.

```
Вход:  _X1, _Y1, _Y2, _FG_COLOR, _BG_COLOR, _WRT_MOD, _DST_PAGE
Выход: —
```

---

## Прямоугольники

### `FILL_RECTANGLE`

Заполненный прямоугольник от `(_X1,_Y1)` до `(_X2,_Y2)` с шаблоном заливки.

```
Вход:  _X1, _Y1, _X2, _Y2
       _FG_COLOR, _BG_COLOR, _WRT_MOD, _DST_PAGE
       _PATPTR, _PATMSK, _CLIP, _XMN_CLIP, _XMX_CLIP, _YMN_CLIP, _YMX_CLIP
Выход: —
Изменяет: все регистры
```
Если `_PATMSK=0`, прямоугольник заливается сплошным `_FG_COLOR`. Иначе — шаблоном из `_PATPTR`.

**Пример (сплошной прямоугольник):**
```asm
    LD   HL,10
    LD   (_X1),HL
    LD   HL,20
    LD   (_Y1),HL
    LD   HL,100
    LD   (_X2),HL
    LD   HL,80
    LD   (_Y2),HL
    LD   A,7
    LD   (_FG_COLOR),A
    XOR  A
    LD   (_PATMSK),A
    CALL FILL_RECTANGLE
```

## Клиппинг

### `TEST_XY_F`, `TEST_XY`, `TEST_XY_L`, `TEST_XY_H`, `TEST_XY_V`

Внутренние функции обрезки. Вызываются автоматически из `GR_LINE`/`HORIZ_LINE`/`VERT_LINE`/`FILL_RECTANGLE`, если `_CLIP<>0`.

```
Вход:  координаты + _CLIP + _XMN_CLIP/_XMX_CLIP/_YMN_CLIP/_YMX_CLIP
Выход: CF=1 если объект полностью за границей (не рисовать)
       CF=0 если нужно рисовать (координаты скорректированы)
```

**Правило:** если `_CLIP=0`, клиппинг отключён и функции возвращают `CF=1` (рисовать). Если `_CLIP<>0`, координаты обрезаются по окну `_XMN_CLIP.._XMX_CLIP` / `_YMN_CLIP.._YMX_CLIP`.

## Внутреннее устройство (для понимания)

### `GR_GET_ADR`

Преобразует `(X,Y)` в физический адрес VRAM и маску. Это **ключевая функция**, которую используют `PUT_PIXEL`, `GET_PIXEL`, `GR_LINE`, `HORIZ_LINE`, `VERT_LINE`, `FILL_RECTANGLE`, `COPY_*` (из `BIOS.SPR`), `DRAW_SPRITE`.

```
Вход:  HL = Y, DE = X, A = страница
Выход: HL = адрес VRAM, A = страница, C = маска
```
Layout VRAM зависит от режима (`SCRMOD`):
- Режим 0 (640×200×2): 80 байт/строку, маска `80H..01H`.
- Режим 1 (320×200×4): 80 байт/строку, маска `88H..11H` (2 бита на пиксель).
- Режим 2 (640×200×4): 160 байт/строку, маска `88H..11H`.
- Режим 3 (320×200×16): 160 байт/строку, маска `AAH/55H` (4 бита на пиксель).

Адрес всегда в диапазоне `4000H..7FFFH` (VRAM), с `SET 6,H` / `RES 7,H` для корректного банка.

---

### `WR_PIX_0..3`, `WR_LINE_*`

Векторы записи. `SET_WRITE_MODE` подставляет `JP` на нужный вариант:

| Режим | `WR_PIX` | `WR_LINE` (для `HORIZ_MAIN`) |
|-------|----------|------------------------------|
| 0 Replace | `WR_PIX_0` | `WR_LINE_*_0` |
| 1 AND | `WR_PIX_1` | `WR_LINE_*_1` |
| 2 OR | `WR_PIX_2` | `WR_LINE_*_2` |
| 3 XOR | `WR_PIX_3` | `WR_LINE_*_3` |
| 4 Transparent | `WR_PIX_0` (с маской) | `WR_LINE_*_4` |
| 5 AND | `WR_PIX_1` | `WR_LINE_*_5` |
| 6 OR | `WR_PIX_2` | `WR_LINE_*_6` |
| 7 XOR | `WR_PIX_3` | `WR_LINE_*_7` |

`WR_LINE_*` оптимизированы для пакетной записи (8 пикселей за раз) и используются в `HORIZ_MAIN`.

---

### `TRANS_COLOR`

Преобразует логический цвет (0–15) в физическую маску для текущего режима.

```
Вход:  A = логический цвет
Выход: A = маска (для WR_PIX)
```
В режиме 0 (2 цвета) — `00H/FFH`. В режимах 1–2 (4 цвета) — `00H/C0H/0CH/CCH/…`. В режиме 3 (16 цветов) — `00H/C0H/0CH/…/FFH`.

---

### `CONV_LN_MASK`

Раскручивает `_LN_MASK` (word) в `GR_BUFFER` (16 байт) для `HORIZ_LINE`. Учитывает режим экрана.

---

### `NEXT_LINE` / `PREV_LINE`

Переход к следующей/предыдущей строке VRAM. Учитывает режим экрана и банк (`SET 6,H` / `RES 7,H`).

---

### `DIVISION`

Деление `HL / DE` (для `GR_LINE` и `FILL_RECTANGLE`). Возвращает `HL = частное`, `DE = остаток`.

---

## Ограничения

1. **Не подключён к `BIOS.MAC`.** Нужно добавить `INCLUDE BIOS.GRP` вручную.
2. **Зависит от `BIOS.SCR`.** Использует `SCRMOD`, `PALTAB`, `BUFSYM1`, `BUFSYM2`. Линковать после `BIOS.SCR`.
3. **Зависит от `BIOS.MAC`.** Использует `WR_PSG`, `CPHLDE`, `CPHLBC`, `DIVISION` (последняя — в `BIOS.GRP`).
4. **Нет аппаратного ускорения.** Всё рисуется программно, побайтово. `FILL_RECTANGLE` на весь экран 320×200×16 может занять заметное время.
