# 06. Клавиатура

Клавиатура в Aleste — тема с подвохом. Физически на машине
стоит клавиатура от MSX, с характерными пятью функциональными
клавишами. Но на уровне портов процессор видит обычную
CPC-матрицу — потому что между клавиатурой и процессором
стоит логика, которая переводит MSX-матрицу в CPC-матрицу.

Что это значит для программиста: **ты работаешь с CPC-матрицей,
а не с MSX-матрицей**. Это важно, потому что в MSX-мире
клавиатура устроена иначе, и если ты привык к MSX — придётся
переучиться.

Плюс есть десять дополнительных клавиш, которых на CPC не было.

## Как устроена матрица

Клавиатура — это матрица. Есть строки (rows) и столбцы (columns).
На пересечении — клавиша. Процессор выбирает строку, читает
столбцы, и по тому, какой бит равен нулю, понимает, какая
клавиша нажата.

В Aleste матрица — 11 строк по 8 бит. В CPC было 10 строк,
в Aleste — 11. Одиннадцатая строка (номер 10) — это как раз
дополнительные клавиши.

## Порты

Клавиатура подключена через микросхему 8255 (PPI), как
и в CPC.

| Порт    | Что                         | Направление          |
|---------|-----------------------------|----------------------|
| `#F6XX` | PPI Port C (младшие 4 бита) | Выбор строки         |
| `#F4XX` | PPI Port A                  | Чтение данных строки |
| `#F7XX` | PPI Control Register        | Направление портов   |

<!-- FIX: добавлен порт #F7XX (регистр управления 8255) — без него
     нельзя настроить направление портов, и примеры ниже не работают. -->

Порядок чтения:

1. Записать номер строки (0–10) в младшие 4 бита порта C.
2. Прочитать порт A.
3. В прочитанном байте каждый бит соответствует клавише
   в этой строке. 0 = нажата, 1 = не нажата.

Логика инвертирована: нажатая клавиша даёт 0, ненажатая — 1.
Это стандарт для CPC-матрицы.

### Настройка 8255

Перед первым чтением матрицы нужно настроить 8255 так, чтобы
порт A был входом, а порт C — выходом (младшие 4 бита).
Обычно BIOS уже это сделал при старте, но если ты работаешь
с 8255 сам — не забудь.

Регистр управления 8255 находится по адресу `#F7XX`. Формат:

```txt
бит 7 = 0       — режим I/O (не bit set/reset)
биты 6–5        — режим группы A (00 = mode 0)
бит 4           — направление порта A (0 = выход, 1 = вход)
бит 3           — направление порта C (старшие 4 бита, 0 = выход)
биты 2–1        — режим группы B (00 = mode 0)
бит 0           — направление порта C (младшие 4 бита, 0 = выход)
```

Для «порт A = вход, порт C = выход (все 8 бит)» нужно значение
`%10010000` (`0x90`): бит 7 = 1? **Нет:** бит 7 = 1 — это bit
set/reset. Для режима I/O нужно **бит 7 = 0**, бит 4 = 1 (порт A
вход), биты 3 и 0 = 0 (порт C выход). Итого `%00010000` (`0x10`).

<!-- FIX: в исходном тексте было %10000000 — это bit set/reset,
     а не настройка направления. Правильное значение — %00010000. -->

```asm
; Настройка 8255: порт A = вход, порт C = выход
LD BC, #F700      ; регистр управления 8255
LD A, %00010000   ; mode 0, порт A вход, порт C выход
OUT (C), A
```

### Логические коды (что возвращает `NORMTAB`)

Эти значения соответствуют таблице `NORMTAB` из `BIOS.DRV`
(индексы 0–87). Для строк 0–8 они совпадают с физической
раскладкой (с точностью до регистра). Для строк 9–10 —
**не совпадают**, потому что `NORMTAB` содержит не физические
метки, а логические коды (управляющие символы, коды джойстика
и т.п.).

| 10     | 0x5F  | 0x12  | 0x18  | 0x84  | 0x83  | 0x82   | 0x81  | 0x80 |

**Важно:** если ты пишешь программу, которая читает матрицу
напрямую через `SNSMAT`, ты получаешь **биты** (0 = нажата).
Если ты хочешь получить **символ**, используй `READ_KEY`/`INPUT`/`INKEY`
из BIOS — они сами преобразуют логический код через `NORMTAB`
(или `SHIFTAB`/`RUSTAB`/`SHRUSTAB` в зависимости от режима).

## Дополнительные клавиши

Десять клавиш, которых не было на CPC.

В строке 10:

- **F1/6, F2/7, F3/8, F4/9, F5/10** — функциональные клавиши
  MSX-стиля. Каждая совмещает две функции: F1 и F6, F2 и F7,
  и так далее. Какая именно сработает — зависит от того,
  нажата ли клавиша SHIFT или другая модифицирующая.
- **HELP** — клавиша помощи.
- **INS** — вставка.
- **b** — дополнительная клавиша (назначение зависит
  от программы).

В строке 9:

- **R/L** — русский/латинский режим. Бит 6.

Ещё есть клавиша **RES** — сброс. Она не в матрице,
а подключена напрямую к сигналу `/RESET` процессора.

И четыре клавиши над цифровой клавиатурой, назначение
которых неизвестно. Возможно, они не используются или
дублируют другие.

## Раскладка JCUKEN

Клавиатура Aleste — не QWERTY и не AZERTY, а **JCUKEN** —
русская раскладка. Это значит, что клавиши расположены
не так, как на привычной клавиатуре.

Например, клавиша, которая на QWERTY-клавиатуре была бы «Q»,
на JCUKEN — «Й». Клавиша «A» — «Ф». И так далее.

Но тут есть тонкость. На уровне портов процессор видит
CPC-матрицу, и BIOS назначает клавишам значения в зависимости
от выбранного режима (русский/латинский). В латинском режиме
работает одна раскладка, в русском — другая.

Переключение между режимами — клавиша **R/L** (строка 9,
бит 6). Эта же клавиша используется как Fire3 для джойстика
(потому что на CPC-джойстике был недокументированный третий
fire, и его решили совместить с R/L).

## Пример: прочитать нажатие

Допустим, мы хотим узнать, нажата ли клавиша «1» (строка 8,
бит 0).

```asm
; Настройка 8255: порт A = вход, порт C = выход
; (если BIOS уже настроил — можно пропустить)
LD BC, #F700      ; регистр управления 8255
LD A, %00010000   ; mode 0, порт A вход, порт C выход
OUT (C), A

; Выбираем строку 8
LD BC, #F600      ; порт C
LD A, 8
OUT (C), A        ; младшие 4 бита = 8

; Читаем порт A
LD BC, #F400      ; порт A
IN A, (C)

; Проверяем бит 0
BIT 0, A
JR Z, KeyPressed  ; если 0 — клавиша нажата
```

Обрати внимание: перед чтением порта A нужно настроить

## Пример: прочитать все клавиши

Обычно в программе есть процедура, которая пробегает
по всем строкам и собирает состояние клавиатуры в буфер.

```asm
; Буфер из 11 байт, по одному на строку
ReadKeyboard:
    LD HL, KeyBuffer
    LD B, 11           ; 11 строк
    LD C, 0            ; номер строки (младший байт BC)
    LD D, #F6          ; старший байт порта C
ReadLoop:
    LD A, C
    LD C, D            ; C = #F6, но нам нужен BC = #F6xx
    ; ...
```

<!-- FIX: в исходном примере C использовался и как счётчик строки,
     и как младший байт BC для OUT (C),A — конфликт. Здесь показан
     корректный подход: счётчик строки — в отдельном регистре (например, E),
     а BC используется только для порта. -->

**Корректный вариант:**

```asm
; Буфер из 11 байт, по одному на строку
ReadKeyboard:
    LD HL, KeyBuffer
    LD E, 0            ; номер строки (счётчик)
    LD B, 11           ; всего строк
ReadLoop:
    LD A, E
    LD BC, #F600       ; порт C
    OUT (C), A         ; выбираем строку
    LD BC, #F400       ; порт A
    IN A, (C)          ; читаем
    LD (HL), A         ; сохраняем
    INC HL
    INC E
    DJNZ ReadLoop
    RET
```

<!-- FIX: переписан пример — счётчик строки в E, BC только для порта.
     Синтаксис OUT/IN исправлен. -->

После этого в `KeyBuffer` лежит состояние всех клавиш.
Ноль в бите — нажата, единица — не нажата.

## Автоповтор и задержка

В SETUP (меню настройки Aleste) можно задать параметры
автоповтора клавиш:

- **Delay** — задержка перед началом автоповтора.
- **Repeat** — скорость автоповтора.

Эти параметры обрабатываются BIOS. Если ты пишешь свою
программу и хочешь свой автоповтор — делай его сам,
не полагайся на BIOS.

## Клавиша RESET

Клавиша **RES** подключена напрямую к сигналу `/RESET`
процессора. Это аппаратный сброс, не программный.
При нажатии машина перезагружается.

Программно нажать RESET нельзя — но можно инициировать
сброс через другие средства (например, через FDC или
через специальные порты). Обычно это не нужно.

## Особенности для программиста

**Ты работаешь с CPC-матрицей.** Не с MSX. Забудь про
MSX-раскладку, если знал её.

**Одиннадцать строк, а не десять.** Строка 10 — новая.
Старый CPC-софт её не знает и не увидит.

**R/L совмещена с Fire3.** Если твоя программа читает
джойстик и ожидает Fire3 — она получит сигнал от R/L.

**Раскладка JCUKEN.** Клавиши расположены не как
на QWERTY. Если пишешь что-то, где важно физическое
расположение — учти.

**BIOS обрабатывает раскладку.** Если не хочешь возиться
с раскладкой сам — используй BIOS-функции чтения клавиатуры.
Они вернут уже готовый символ с учётом режима.

**Строки 9–10 в `NORMTAB` — не физические метки.** Если
ты читаешь матрицу напрямую через `SNSMAT`, ты получаешь
биты. Если хочешь символ — используй `READ_KEY`/`INPUT`/`INKEY`,
они преобразуют логический код через `NORMTAB`.
